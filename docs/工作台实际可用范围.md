# HOMA 工作台实际可用范围

打开工作台，先看左下角的数据来源。原网址提供静态页面，可以在当前浏览器练习分派、填写表单和广告复盘。在这里录入的内容不会出现在同事的账户中。办理下表中的团队业务，需要使用连接 FastAPI 和 PostgreSQL 的完整服务，登录个人账户。本文按 2026 年 11 月 25 日的源码核对，以产品总览为第一项，左下角「功能覆盖与系统设置」为第十七项。[完整服务运行方式](../README.md#运行模式)

| 左侧入口 | 在完整服务里可以办到哪一步 | 哪一步还要另办 |
|---|---|---|
| 产品总览 | 按仓库权限找到待审批采购、待收货、待付余额或异常包裹，点进原单处理，再刷新核对。选产品后可查期间指标和计算依据。 | 跨仓待办和单个产品的经营指标范围不同。多店销售日报需要有权限的人员导入。 |
| 产品交付清单 | 按型号找缺件，登记文件或文件夹链接、版本和准备状态，导出清单交接。 | 链接访问权限在原文件系统授予。准备状态由经办人核实，文件内容的审核在审批单办理。 |
| 流程协作 | 管理员配置填写项、办理人、前置条件和审核顺序。经办人上传附件，指定审核人退回或通过，可追溯到当次提交。 | 提醒和催办需要人员跟进。飞书消息与邮件尚未接通。 |
| 全流程 SOP | 从产品任务进入阶段审批单，核对前置项、版本、计划和实际时间。退回后可修订，完成事项重新打开后再改。 | 实验室检测、物流签收等由相关机构完成，责任人把取得的凭证放进该阶段。 |
| 团队与审批 | 查看部门负载、待我办理和待我审核，进入对应事项完成交接或审核。 | 开通账号、指定审核人和授予仓库权限需管理员分别办理。当前适用于一个受控团队工作区。 |
| 店铺与账户 | 不选产品也可按店铺、站点登记一个 Case，记录来往、负责人、复核意见并关联后续单。 | 开 Case、回复客服、读取新的绩效通知仍在 Seller Central 办理。 |
| Listing 与素材 | 发起一次主图或文案改版，交接版本、验收记录与发布凭证。有来源数据时可核对该 SKU 的流量与转化。 | 上传素材、发布或恢复受抑制页面须由有权限的人在亚马逊操作。 |
| 广告运营 | 汇总有明确粒度的搜索词报告。为一次广告调整登记基线、观察期和归因窗，附执行凭证，到期复核，日／周／月查看待办与结论。 | 调竞价、预算、否词及核对生效回执仍在广告后台办理。SP 商品报告的自动读取需店铺授权。手工导入值不能证明亚马逊已经刷新归因。 |
| 备货与库存 | 采购申请经另一人审批后签发采购单，仓库按实到数分批接收和质检，良品可在两个获授权的仓之间调拨，库存台账同时更新。 | 供应商接单、承运和外仓收货仍需外部回执。FBA 库存读取另需授权。 |
| 活动与排期 | 新建活动或节点，查当天工作和任务截止日，在月历、周历中滑动或缩放。活动准备和上线回执可交接给复核人。 | 报名、资格确认及平台优惠设置由经办人在亚马逊完成。 |
| 成本与利润 | 财务按有合同价的实收行逐行核对发票、立应付、分笔登记付款凭证。可按结算单登记流水，核对到账差额和分摊费用。 | 银行转账需另办。旧无价行走人工登记。当前匹配按同币种、按件、按单次实收行整行结算。独立运费、折扣和税差另行处理。 |
| 订单与售后 | 登记自发货订单、分包、放行及截单结果。按订单行核对分次退款，退件可登记到货并按实物处置，形成相应库存记录。 | 向平台标发、发起退款、向承运商请求截单仍在原系统执行，工作台登记结果与凭证。 |
| 产品与合规 | 记录产品声明依据、送审资料、机构反馈与证书，按阶段退回、补件、验收。 | 法规适用性和证书有效性由对应责任人或机构核实，平台申报另办。 |
| 排名监控 | 保存关键词、站点、邮编等观察条件，分别查看已有自然位、广告位及 BSR 历史。人工位次或缺测情况可写入办理单。 | 自动排名采集器尚未接通。填完观察单不会自动生成曲线数据，空图表示缺观测。 |
| Agent 决策中心 | 按产品和页面查看有证据的异常或规则建议，人工决定是否建跟进单，记录执行与复核。 | 模型起草需配置供应商。建议本身不会调广告、改 Listing 或通过审批。 |
| 数据导入中心 | 管理员选产品，下载对应标准模板、预校验、提交有效记录，检查导入批次。店铺结算 CSV 和多店销售日报另在对应台账导入。 | 原始文件需符合所选口径。账号、SKU、币种和报告粒度要能核对。未知数据源需要另做映射。 |
| 功能覆盖与系统设置 | 管理员配置数据源、SKU 映射和参数，查看同步作业与最近有效数据。部署启用升级进程后，可手动检查并升级。 | 亚马逊真实授权、团队长期服务和备份恢复需在对应环境验收。升级从正式分支取代码，草稿 PR 不会进入正式版。 |

**日报与飞书总表。** 在产品总览展开「把一段运营记录分给对应岗位」，填写原文。点击「识别并预览」，系统按用词给出候选页面，经办人确认对象和去向，再保存成单并交给下一位。个人原文、已分派的业务单和排期是三种记录。确认一项工作是重点后，在该单的「工作重点日期」选一天并保存。原单会出现在活动月历、周历和排期清单，点开即可继续办理。草稿改期或清空日期后，日历据同一张单更新。管理员配置总表后，经办人、指定审核人或管理员可打开已提交工作单，手动同步到飞书，再点原记录核对。失败重试沿用同一工作单标识。飞书只接收本地ID、类型、事项、产品、负责人、状态和板块七个文本字段。个人未分派原文和附件保留在工作台。飞书端测试使用模拟接口，真实租户权限与写入仍需用自己的表核验。

**首次连接飞书。** 在飞书开放平台创建企业自建应用，由租户管理员开通多维表格读写权限、发布应用并授予目标表编辑权限。在表里准备上述七列，字段类型选文本。数据库管理员无需提供飞书个人账号。部署管理员在 Docker 的私有配置中填写 `HOMA_FEISHU_APP_ID`、`HOMA_FEISHU_APP_SECRET`、`HOMA_FEISHU_BASE_TOKEN` 和 `HOMA_FEISHU_TABLE_ID`。本机正式工作区使用实例目录中的 `integrations.env`，保存后重新启动工作区。常规 Compose 部署使用项目私有的 `.env`，然后重建 API 容器。先选一张允许发送的工作单，核对飞书原记录中的七列和工作单状态，再交给同事使用。

**如何核验。** 专业表单的提交、审批、登记执行、复核共享一套工单流程。表单进入「已执行」表示经办人登记了结果。复核外部动作时应核对原系统回执。五类专项验证分别覆盖业务单据、多人办理、阶段审批、来源计算和广告复盘。[ERP 单据与测试](ERP测试记录.md) · [多人办理与月历](workbench-validation.md) · [阶段审批](approval-validation.md) · [报表与计算](data-automation-validation.md) · [广告复盘页面验证](../scripts/check_ads_reviews.cjs)
