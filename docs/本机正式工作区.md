# 在自己的电脑上启动 HOMA 正式工作区

首次启动后，工作台有部门、流程模板和业务表结构。商品、员工、业务单与经营数据从零开始。这台电脑保存业务数据，默认访问地址是 `http://127.0.0.1:14681`。

## 首次开通

1. 在 macOS 启动 Docker Desktop，在 Linux 启动装有 Compose v2 的 Docker Engine。首次构建需要能拉取服务镜像和 Python 依赖。宿主机只需 Docker Compose、Bash 和系统自带命令。
2. 把同版本源码解压到自己的目录。Mac 双击顶层 **启动工作台.command**，启动成功后会打开工作台。Linux 在项目目录运行 `bash scripts/local_workspace.sh start`，再打开终端显示的本机地址。Mac 也可以使用这条终端命令。
3. 打开页面顶部的 **登录协作账户**。首位用户会看到 **管理员设置码**。打开终端提示的 `admin-setup-code` 文件，把内容填进去，再输入自己的姓名、邮箱与至少 12 位的密码，点击 **创建管理员并登录**。设置码与数据库口令分别保存在本机私有配置目录，启动日志只显示文件位置。
4. 在 **产品总览 → 新建产品** 录入自己的型号，系统据此生成 SOP。进入该产品的 **流程协作 → 成员与账户**，为员工创建个人登录，再分配执行与审批职责。初始工作区没有通用管理员密码。

日常使用可从已安装的工作台图标进入。支持安装的 Chrome 或 Edge 可从正式工作台页面选择安装。macOS Sonoma 14 及以上也可在 Safari 的 **文件 → 添加到程序坞** 中创建独立窗口。Docker 运行时，都连接同一个本机地址和数据卷。

## 启动、停止和配置

在项目目录运行以下命令。

```bash
bash scripts/local_workspace.sh start
bash scripts/local_workspace.sh status
bash scripts/local_workspace.sh stop
```

`stop` 保留数据库和上传附件。再次运行 `start` 会使用原有配置和数据卷，按当前目录中的源码构建服务并执行尚未应用的迁移。更新版本前先备份，再从可信的新版本目录运行 `start`。本机入口使用独立 Compose 项目 `homa-local-main`，对外发布的端口仅绑定本机回环地址。

| 系统 | 默认私有配置目录 |
|---|---|
| macOS | `~/Library/Application Support/HOMA/workspaces/main/` |
| Linux | `${XDG_STATE_HOME:-$HOME/.local/state}/homa/workspaces/main/` |

`integrations.env` 是权限为 0600 的本机配置文件。按实际开通的服务填写一行一个 `KEY=value`，保存后重新运行 `start`。飞书使用 `HOMA_FEISHU_APP_ID`、`HOMA_FEISHU_APP_SECRET`、`HOMA_FEISHU_BASE_TOKEN`、`HOMA_FEISHU_TABLE_ID`；Amazon 和模型服务可填写项目支持的 `AMAZON_SP_API_*`、`AMAZON_ADS_*`、`LLM_API_BASE`、`LLM_MODEL`、`LLM_API_KEY`。新装时这些凭据为空。请将本机私有配置保存在源码目录以外。

如默认端口已有服务占用，可在首次安装前指定另一空闲端口，例如 `HOMA_LOCAL_PORT=14682 bash scripts/local_workspace.sh start`。所选端口随后保存在实例配置中。若已有同名 Docker 资源而本机实例标记不相符，启动脚本会中止。请找回原私有配置，或用另一个新实例名和新端口启动，避免误用旧数据卷。

## 备份与恢复

备份前启动工作区，然后运行以下命令。完整备份会短暂停止 Web 和 API 写入，同时保存数据库和上传附件。服务恢复就绪后，最后一行显示备份目录。

```bash
bash scripts/local_workspace.sh backup
```

把整个备份目录保存到受保护的位置，其中包含 `db.dump`、`uploads.tar` 和 `SHA256`。备份含业务资料和账户密码哈希；请另行妥善保管本机 `integrations.env`。恢复默认沿用备份中的员工账户和密码，并使用新实例的数据库口令。

恢复需要**新的实例名称和空闲端口**。用当前或向后兼容的工作台版本执行下例，源实例仍保留原数据。

```bash
HOMA_LOCAL_INSTANCE=recovered HOMA_LOCAL_PORT=14682 \
  bash scripts/local_workspace.sh restore "/完整路径/备份目录"
```

脚本先校验两份备份文件，再写入该实例专属的新数据库和附件卷；同实例现有业务库拒绝原地覆盖。打开新地址后登录，核对商品、单据和附件。后续管理该实例时加 `HOMA_LOCAL_INSTANCE=recovered`。若恢复过程中断，可对同一新实例、同一备份再次执行 `restore`。如外部服务也需启用，可把已核对的连接配置填入新实例的 `integrations.env`。

默认数据库卷为 `homa-local-main_database`，上传卷为 `homa-local-main_uploads`。保留它们和私有配置目录，Docker 清理数据卷可能导致原账无法打开。若提示管理操作正在进行，先等待其他启动、备份或恢复完成。异常关机后，确认没有相关脚本或 Compose 操作在运行，才可移除本实例私有配置中的 `operation.lock/pid` 与空的 `operation.lock` 目录并重试。
