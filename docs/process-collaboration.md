# 流程协作 · 第一版

进入左侧「流程协作」，按产品查看可点击流程图、节点清单和时间排期。与原有 SOP 使用相同的任务 ID 和状态，不另建一套执行进度。图中四个区域是工作分类，只有实际连线才代表必须完成的前置关系；同阶段允许并行，管理员也可配置跨阶段依赖。

## 首次使用

1. 部署或升级后执行 `sh scripts/migrate.sh`，包括新增的 `007_process_collaboration.sql`。
2. 在受信任的服务器终端运行 `docker compose exec api python -m app.workflow_auth` 获取管理员设置码。设置码是敏感凭证，不要提交、截图、贴到聊天或发给普通成员。也可通过部署环境安全注入 `WORKFLOW_SETUP_TOKEN`。系统没有默认管理员密码，首位管理员建立后不再接受管理员注册。
3. 前端点击「首次设置管理员」，输入设置码、姓名、邮箱和至少 12 位密码。只有持有码的人可以完成初始化。
4. 在「成员与账户」为实际人员建立独立登录账户。新增成员没有配置权；已有人员档案可用相同邮箱关联，但不能覆盖已有登录账户。
5. 选择产品，点击「启用未配置节点」。每个未完成节点生成初始表单，默认由管理员负责并审核，再逐项分配真实人员。已有配置不会被覆盖，已完成节点不会自动重新打开。旧版 10 项示例任务会在没有前置关系时建立标准上线依赖。
6. 点击节点 →「配置节点」，指定负责人、协作人、审核人、计划时间、地点、前置节点和填写项目。配置仅针对当前产品的这个节点。

云环境使用仓库外的启动覆盖时，先设置平台 Start skill 中的 `COMPOSE_FILE`，再执行上述 Docker 命令。当前工作区可用：

```bash
export COMPOSE_FILE=/workspace/-agent-/docker-compose.yml:/workspace/homa-setup/compose.yaml
bash /workspace/homa-setup/start.sh
```

## 表单与协作

支持单行文字、多行说明、数字、日期、单选、多选、人员、地点、附件。每项可独立设置名称、说明和是否必填。附件支持实际文件上传（单文件最多 10 MB）和 HTTP(S) 资料链接，可记录版本。外部资料沿用原平台权限，系统不会读取链接正文。

默认事项按产品合规、Listing、广告、库存、财务等工作内容设计，包含工作说明、核对结果和交付附件。负责人及协作人填写，管理员可协助处理。未完成前置时允许保存准备资料，但不能提交验收。

审核支持会签（全部通过）、或签（任一通过）和顺序审核。只有指定审核人可以审核，管理员身份不自动取得审核资格。退回必须说明原因，重新提交生成新版本。通过审核后任务自动完成，与 SOP 清单同步。

“我负责 / 协作”和“待我审核”按当前个人账户筛选。当前没有邮件、飞书消息或后台通知调度。

## 权限与历史

- 只有首次建立的流程管理员可以配置字段、分配人员、指定审核人和维护前置关系。`app_users.role_code`、客户端传入的角色或人员 ID 都不提供配置权。
- 普通成员只能填写自己负责或协作的节点；只能审核自己被指定审核的节点。服务端验证全部写入权限，前端隐藏配置入口。
- 未登录可只读查看节点要求和流程结构；填写内容、提交历史和文件下载要求登录。本版是单一工作空间，登录成员可查看该空间的提交记录；没有跨组织或逐产品的数据访问隔离。原有工作空间和部分经营 API 仍有公开读取能力，不代表全站已实现身份隔离。
- 配置、草稿和审核使用版本检查，拒绝并发覆盖。变更审核中的配置必须明确撤回当前提交，旧审批不会自动适用于新版本。
- 完成后配置不能直接覆盖。管理员可填写原因重新打开节点，并撤回已启动的后续节点的验收状态，保留原始提交、配置快照和意见。
- 已启用协作的节点拒绝旧状态/审批/证据接口写入，避免绕过动态表单及指定审核人。人员、任务要求等旧配置接口也要求管理员登录。
- 会话为 12 小时的 HttpOnly、SameSite=Strict Cookie，服务端存储令牌摘要。密码使用 PBKDF2；连续错误登录会临时锁定账户。写入同时检查来源和自定义请求头。

## 文件与部署

文件默认保存在 API 的 `/var/run/amazon-agent/workflow-uploads`；Compose 的 `update_state` 卷保留这些文件和设置码。备份时必须同时备份 PostgreSQL 与此卷，不应只备份数据库。可通过 `WORKFLOW_UPLOAD_DIR` 和 `WORKFLOW_SETUP_TOKEN_FILE` 指定其他持久目录。生产 HTTPS 部署应设置 `WORKFLOW_COOKIE_SECURE=true`，并正确传递可信代理的主机和协议；设置代理时保持来源检查生效。

第一版没有通用流程模板编辑器、账户自助找回密码、多人管理员授权、飞书同步或通知调度。配置当前产品节点已可使用，不宣称这些外围功能已经完成。原有产品文件索引与流程表单的附件登记为各自入口；已启用协作节点的交付以流程提交快照为准。

## 验证

纯逻辑验证可用 README 中的开发检查。数据库集成测试在运行的 Compose API/数据库上执行：

```bash
bash scripts/test_process.sh
```

脚本创建 `homa_workflow_test_*` 临时数据库并应用全部迁移，运行包括权限、三种审核模式、并发修改、版本撤回、依赖、附件隔离和下游重新验收在内的测试，结束后删除测试数据库。不会对业务数据库执行测试写入。可使用平台提供的 `COMPOSE_FILE` 覆盖。
