# 全流程 SOP 审批模板覆盖表

本版为目录中的全部 **79 项事项**配置了明确的业务审批模板。模板仅提供事项表单、办理步骤、审核环节和退回路径；实际负责人、审核人、原计划、预计与实际时间由具体产品的审批单记录。预设步骤不表示认证、测试、发货或其他真实业务已完成。

## 合规事项拆分

- **FCC 认证**：7 个环节，覆盖申请资料、内部审批、机构接单测试、草稿反馈、草稿审核修订、正本签发接收和最终归档验收。草稿审核退回到草稿反馈，验收退回到正本接收。
- **危险品判定**：5 个环节，覆盖材料提交、机构或平台接单评估、正式结果反馈、内部复核及运输条件归档。
- **标签确认**：5 个环节，覆盖信息汇总、设计初稿、合规与编码核对、修订定稿及印刷或使用验收。其前置依赖包含 FCC 和危险品判定事项。
- 旧 `certification`、`dangerous`、`label` key 与旧综合事项标题均有兼容映射。现有任务 ID、证据、原单节点表单与审批历史应保留；多阶段新单据使用自己的定义快照。已有完成记录不会因新增模板而被宣称经历过这些新环节。

## 维护与验证

- API 使用 `backend/app/approval_templates.py`，静态只读预览使用同源生成的 `frontend/approval-templates.json`。
- 更新模板后在仓库根目录运行 `PYTHONPATH=backend python -m app.approval_templates` 重新生成静态注册表。
- `backend/tests/test_approval_templates.py` 检查 79 项完整覆盖、事项表单唯一性、FCC 7 阶段与退回路径、字段合法性、旧 key 兼容、模板快照独立及静态/API 一致性。
- 变更模板不会直接修改已运行审批单；已有单据按保存的定义版本执行，配置变更必须遵循明确撤回与重送审规则。
- 目录为默认业务流程设计，实际法规适用性、证书或报告真实性、外部机构承诺及文件权限仍需要业务人员核实。
