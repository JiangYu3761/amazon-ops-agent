# HOMA ERP 业务办理与验收

工作台使用自己的 PostgreSQL。经办人可以从首页待办处理一笔业务，也可以从左侧的订单售后、库存、财务和广告进入相应单据。工作台登记经办人、来源凭证、状态与数量；实际付款、平台退款、物流发货需以原系统实际回执为依据。

## 首次运行

1. 按项目 README 的 Docker Compose 步骤设置数据库密码和连接串，启动后进入工作台。手工部署既有库时，API 启动会持有迁移锁依序安装新版本。正式升级前应有可恢复的备份。[项目运行说明](../README.md)
2. 依照流程协作说明设置首位管理员，再创建申请人和仓库经办人。采购申请需要不同的经办人和管理员完成自审隔离。[账号开通](process-collaboration.md)
3. 在库存模块打开「仓库收货」，以管理员建立店铺、站点、业务时区及仓库，勾选能办理该仓库的成员。跨仓调拨需为经办人授权同店铺、同站点的两个仓库。用户只看得到已获授权的范围。
4. 在服务器连接状态下办理正式单据。纯静态预览可用于熟悉原工作台，ERP 事务由 FastAPI 和 PostgreSQL 执行。财务和库存凭证请用可回查的单据号或报告行号。

## 从总览开始

「ERP 待办」列出可访问仓库的未完成动作，优先显示截单失败、已出库后取消等异常。可从待办定位包裹、采购申请、收货单或供应商账单。审核通过、待检清零、结清付款或处理完异常后，刷新待办即可核对结果。商品经营环比单独按当前选择的产品与时区计算。

## 经办入口

| 在哪里办 | 经办人输入及动作 | 如何核对结果 |
|---|---|---|
| 库存 → 采购申请 | 选仓填写供应商、申请依据、SKU 和件数。有合同价时逐行录入币种、每件净价和每件税额，再提交复核。另一位管理员批准或填写驳回理由，申请人可修改重提。批准后签发正式采购单。 | 详情可查看历次申请的数量和价格。签发后的采购行保留获批合同价，可从详情进入对应仓库的采购单。并发签发只会生成一张。 |
| 库存 → 仓库收货 | 从已下单基线或已签发采购单开始，逐行分批通知到货。本次实收可少于通知。普通收货进入待检，质检分别登记良次，免检转良品。快捷收货直接登记良次。 | 查看已通知、实收、剩余可通知、待检、良品和次品，以及原事件和冲销事件。后续质检、应付或库存占用会限制撤销。 |
| 库存 → 仓库收货 → 扫码收货 | 选择仓库，扫描或输入采购单号、收货通知号、SKU 或已登记 FNSKU。多笔命中时选择具体通知再确认数量。管理员可在扫码区维护本仓 FNSKU 与采购 SKU 的对照。 | 显示匹配的采购行，已收通知移出候选；扫码定位本身不增加库存。浏览器验证了键盘输入模式。 |
| 库存 → 库存余额与调拨 | 按授权仓和 SKU 查待检、良品、次品。两仓核实交接后录入调拨单号、来源凭证和良品件数。 | 一次保存同时减转出仓、增转入仓。重复凭证可核对，库存不足会阻止过账。 |
| 订单与售后 → 自发货履约 | 录平台来源或手工订单及商品行，确认收款，按件分配包裹。每个包裹分别审核、放行，登记仓库出库或承运商回执。 | 未确认收款不可放行。买家取消在放行前暂停，在放行后等待仓方截单；截单失败可再催截。已出库的包裹保留跟进直到取得相应回执。 |
| 订单与售后 → 退款核对台账 | 按产品、店铺和订单行登记可退金额。人工标记可加或撤；核对过的外部退款按结算单、流水行、日期、金额和币种登记。 | 逐笔保留流水。撤人工标记不影响真实已登记金额。一个订单行可对应多笔退款。 |
| 同一订单行 → 退货包裹 | 登记包裹、来源类型、实收件数和收货凭证，分次处置良品、次品、销毁。 | 核对实收、待处理和已处置合计。本地实物库存按过账凭证核对；FBA 和第三方仓记录依赖外部报告。退款进度单独保留。 |
| 财务 → 供应商应付 | 选择同仓同供应商的实收行，对照实际发票，录入单位、件数、净单价、行税额、行含税金额及整票金额。匹配通过后建立应付，再按真实付款凭证分笔登记。 | 有合同价时系统逐行比较，短收按实收量计算，差额会阻止入账。旧无价采购行走人工凭证登记，台账可查金额依据、已付和余额。有效账单锁定来源；未付款的错误账单由管理员说明原因并作废。 |
| 财务 → 店铺结算对账 | 按店铺、站点、币种建结算单，填期初、期末留存、实付和凭证，导入带原单日期的交易 CSV。 | 按发放日归期。应打款等于期初加有符号交易减期末留存。页面同时显示实际打款和差额；更正保留反向流水和修订历史。 |
| 财务 → 店铺结算对账 → 费用分摊 | 在原费用行选择同一币种的产品或 SKU，填写权重与依据。预览分配和合计后确认，保留版本与经办人。 | 30 USD 按 2∶1 得到 20 和 10。最小货币单位按余数分配，尾差可追溯。原费用冲正或发放日变更时旧归集失效。 |
| 广告 → 搜索词汇总 | 选择产品，在页面下载模板，提交显式包含搜索词粒度、广告账户、活动、归因窗及币种的 SP/SB 报告。 | 点开来源行。先加总费用、归因销售、展示和点击再计算 ACOS、CPC 和 CTR；缺分母留空。关键词定向报告以外的粒度尚待扩展。 |
| 总览 → 多店经营 | 管理员导入明确店铺、站点、日期与币种的日报。按自己的授权范围核对销售额、件数与订单数。 | 同店授权到两座仓库只统计一次，原币分别小计，缺报保持空值，可回到原文件和具体行。 |
| 总览 → 经营环比 | 选产品、截止日期和天数，比较两个已结束的等长期间。 | 可展开 8 个指标的来源、公式和覆盖日期。上期 -100、本期 -80，对应 +20%；上期为零只显示差额。 |

## 可以自己复核的一天

使用虚构数据在独立测试库试办。准备同店同站的 A、B 两仓，一位采购申请人、一位管理员、一位两仓均获授权的经办人。

1. 申请采购 SKU-A 共 100 件、SKU-B 共 40 件。驳回一次后修改重提，换管理员批准并签发。再次点击签发时检查采购单号。
2. SKU-A 分两批通知 60 和 40。第一批实收 60，免检 15，再验良 42、次 3。A 仓应有 57 良、3 次、0 待检。将 5 良调至 B 仓后，两个仓的良品分别为 52 和 5。
3. 在第一步给 SKU-A 录入 USD 2.00 净单价和 USD 0.10 单件税。60 件实收的发票数量为 60，行税额为 6.00，含税金额为 126.00。将整票金额改为 125.99，核对页面差额，尝试提交。更正为 126.00 后入账，登记首笔付款 51.00，余额应为 75.00。两个经办人同时各登 50.00，只能过一笔。再登 25.00 后余额归零。
4. 一笔三件的自发货订单分为一件和两件两个包裹。未确认收款时核对放行限制。确认收款，放行第一包后登记买家取消；第二包仍可单独办理。仓方拒截时需能看到异常和回执。
5. 同一订单行录入 USD 20 和 USD 5 两笔退款；撤销人工标记后仍显示已登记 25。包裹收到后分别登记实收和处置。
6. 一份结算单填期初 10、销售 +100、费用 −15、跨月退款 −20、期末留存 5，实际打款 68。应打 70，差额 −2。重导同一份 CSV 后再次核对交易行数和余额。

## 验收与业务边界

代码验收使用隔离 PostgreSQL 16、FastAPI 和浏览器页面。数据库测试覆盖并发、不重复入账、拒绝越权、数量/金额守恒、状态纠正和升级旧库。命令和详细测试入口见同目录的验收说明。[验收入口](ERP测试记录.md)

同一张采购单分批收货，可以按不同实收批次分开建账。一笔实收事件中的同一行须整行结算。含单列运费、折扣、税差或一条实收行分多票结算的业务需要另外核算。

仓库授权精确到店铺、站点及仓库。售后退款采用经办人及管理员范围；经营环比和搜索词报表采用现有登录工作区的产品范围。多法人总账、全渠道店铺级字段权限、多币种汇兑、承运商打单、自动向 Amazon 标发或退款等能力仍需各自实现和验收。
