# 工作台验收记录

验收日期为 2026 年 11 月 24 日。使用独立的 PostgreSQL 16、FastAPI、Playwright 1.62.1 和 Chromium 156。模拟经办人及审核人各自登录，所有写入均在临时库完成，结束后删除。浏览器脚本通过界面办理业务，并通过真实 HTTP 接口读回关键状态和来源。

## 实测结果

- 源码目录运行完整后端测试。应用 001 至 011 号迁移后，217 项全部通过，无跳过。包括原有 182 项回归，以及覆盖专业表单、办理权限、跨页关联、经营信号与核算的 35 项工作台测试。
- Compose 的 `scripts/test_process.sh` 同样收集 217 项，201 项通过，16 项因精简镜像缺少源码和 Git 跳过。这 16 项均在上述源码运行通过。
- Chromium 完成下表的页面操作。原有前端经营规则测试、运营记录分派测试、静态前端构建、手册生成一致性检查和 JavaScript 语法检查均通过。

## 复现

在仓库根目录运行。后端需要 Python 3.12 与 `backend/requirements.txt` 中的依赖。浏览器测试另需 Node.js、可解析的 `playwright` 包和 Chromium，默认路径为 `/usr/bin/chromium`，也可用 `CHROMIUM_PATH` 指定。将 `WORKBENCH_TEST_PG` 指向本机测试 PostgreSQL 的连接串，账号需能创建数据库。如需保存当前库存表的实拍图，可将 `WORKBENCH_SCREENSHOT` 设为可写的 PNG 文件路径。脚本只接受回环地址，每次创建并清理一个独立测试库。

```bash
python scripts/check_workbench.py --backend
python scripts/check_workbench.py
node frontend/tests/operating-rules.cjs
node frontend/tests/workbench_routing.cjs
python scripts/build_frontend.py
python scripts/build_workbench_manual.py --check
```

已启动仓库的 Compose 测试栈时，也可运行 `bash scripts/test_process.sh`。该脚本另建临时库。更新流程中的 16 项测试依赖源码、Git 与 POSIX shell，精简 API 容器会跳过。在完整源码环境运行上面的 `--backend` 命令即可覆盖。

使用手册可按页面查找输入、办理步骤和验收样例。[打开运营工作台使用手册](workbench/运营工作台使用手册.html)

外部 Amazon 服务、真实模型供应商以及生产环境部署需在各自接入环境单独核验。这轮覆盖单工作空间内的角色和经办权限。
